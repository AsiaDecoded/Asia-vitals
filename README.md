# Asia Vitals

Data pipeline for Asia Decoded's macro dashboards: GDP, inflation and trade for 12 Asian economies. Currently: Japan GDP, CPI, CPI contributions and PPI; India CPI (headline, core 1 and 2, and a long series from the IMF); Singapore CPI (with MAS core, contributions and diffusion) and producer prices; South Korea CPI (with core measures, contributions and diffusion) and producer prices; Hong Kong CPI (Composite, A, B, C, headline and underlying, sections, groups, COICOP divisions, seasonally adjusted, published contributions and weights), producer prices and import/export unit value indices, all as published.

## How it updates

1. **GitHub Actions** (`.github/workflows/update.yml`) wakes at 08:15 and 11:15 Singapore time but runs a source only on its release days: from the date in `pipeline/release_calendar.json` to the end of a short catch-up window (`pipeline/tools/due.py sources`). On other days it fetches nothing. Each source fetches its data, runs its checks and writes only if there is something new that passes. A failing source writes nothing and doesn't block the others. A manual run with a list of sources (blank = all) ignores the calendar.
2. After every run, `run_report.txt` (what each source did and why any failed, or that nothing was due and the next release day) is pushed to the **run-reports** branch. From 45 days before a group's last calendar date it carries an ACTION warning to add the next dates.
3. **A scheduled task in Claude** copies new data into the Claude dashboards and reports failures. It runs only on refresh days (`pipeline/tools/due.py next-refresh`): the release day for morning releases (Japan, Korea), the day after for releases that reach the repo after 11:15 Singapore time (India, Singapore). Each run first schedules the next one.

## Layout

| Path | Contents |
|---|---|
| `pipeline/run.py` | Runs all sources (or those named), writes the run report and `data/all_long.csv` |
| `pipeline/release_calendar.json`, `pipeline/tools/due.py` | Release dates per source (official calendars, or the agency's usual pattern where none is published); which sources are due on a day, and the next dashboard refresh day |
| `pipeline/sources/` | One module per source; registry in `sources/__init__.py` |
| `pipeline/core/` | Shared: long format, release files, e-Stat and BoJ clients |
| `pipeline/tools/estat_discover.py` | Lists e-Stat tables and their codes (manual workflow `estat-discover.yml`) |

| `pipeline/tools/boj_discover.py` | Lists BoJ series codes (manual workflow `boj-discover.yml`) |
| `pipeline/tools/mospi_discover.py` | Probes MoSPI's CPI and WPI API (workflow `mospi-discover.yml`) |
| `pipeline/core/ecos.py`, `pipeline/tools/ecos_*.py` | Bank of Korea ECOS client and the Korea series store `raw/kr/ecos/store.json.gz`; discovery, backfill and parallel month-fetch helpers (workflows `ecos-*.yml`) |
| `pipeline/core/singstat.py`, `pipeline/tools/singstat_discover.py` | SingStat Table Builder client (paged by data point); probe of price tables (workflow `singstat-discover.yml`) |
| `pipeline/core/censtatd.py`, `pipeline/tools/censtatd_discover.py` | C&SD client: web-table API, Table E501 files, web report tables and annexes, product index, release schedule; probe of Hong Kong price sources (workflow `censtatd-discover.yml`) |
| `raw/<country>/<source>/` | Original files for every release processed, unchanged (CPI: compressed API response) |
| `data/<country>/<indicator>/` | `<country>_<indicator>.csv` (dashboard format), `long.csv` (common format), `json/` (per chart), `release.json`, `release_row.json` |
| `data/all_long.csv` | Every source's long file stacked: the input for cross-country views |

**Common long format:** `country, indicator, series, label, measure, area, freq, date, value, unit, source, release`.

## Checks (errors stop that source)

- **GDP:** all tables and columns present; latest quarter matches the release; q/q, annualised q/q and y/y match the levels; contributions sum to GDP; deflator matches nominal ÷ real. Warning if past levels are revised by more than 2%.
- **CPI:** required series present for the latest national and Tokyo months; months never go backwards; published m/m and y/y match the index where both months are on the 2025 base (earlier rates are the officially published ones from older bases); index levels plausible.
- **PPI:** PPI, export and import (yen) index and y/y present for the latest month; months never go backwards; published y/y matches the index where both months are on the 2020 base; index levels plausible. A revision without a new month is noted as a warning.
- **India CPI:** spliced index present every month from Jan 2011, y/y from Jan 2012, for all three sectors; 2010-base link factor in range; each part where it should be; calculated y/y within 0.15pp of MoSPI's published rate from Jan 2026, and never more than 1.5pp from it before.
- **India CPI, IMF:** one monthly and one annual series, reference period 2024 = 100; no gaps from the first month or year to the latest; months never go backwards; 2024 annual within 1 of 100; IMF y/y within 0.05pp of its own index; warning if any month from Jan 2025 differs from MoSPI's combined CPI by more than 0.02.
- **India core CPI:** 2012-base y/y for 2025 within 0.06pp of the RBI's published Table IV.1 (MPR April 2026); full 2025 overlap for the link; all 358 items present for every month and matching the weights file; weights sum to 100; weighted items reproduce MoSPI's published general index within 0.02 every month.
- **CPI contributions:** all items, fresh food, energy, goods and services found in every month's file; goods + services within 0.1pp of all items; all items within ±15.
- **Hong Kong CPI:** latest month present for the four indices (headline and underlying), 9 sections, meals out, basic food, 13 COICOP divisions, at least 75 groups, the SA 3-month average and the published contributions; no gaps in headline y/y (Composite Oct 1981–, A/B/C Jul 1975–); E501 sections agree with tables 510-60001/60001A; published y/y and m/m within 0.2pp of the published one-decimal indices on the 2019/20 base; published contributions sum to all items within 0.25pp and all items equals published y/y; weights sum to 100 by section and group.
- **Hong Kong producer and trade prices:** latest quarter (PPI) and month (unit value indices) present, never going backwards; no gaps in manufacturing PPI y/y (2006–) or import unit value y/y (1983–); Q2 2026 PPI against C&SD's release.

## Adding a source

Add a module under `pipeline/sources/` with `update(**opts)` returning `{"updated", "code", "summary", "warnings"}` (raise `CheckFailed` on bad data), write `data/<country>/<indicator>/` including `long.csv`, and add its name to `SOURCES`.

## Running by hand

```
python -I pipeline/run.py                         # all sources
python -I pipeline/run.py jp_cpi_estat            # one source (needs ESTAT_APP_ID)
python -I pipeline/run.py jp_gdp_esri --code qe262_2 --from-dir raw/jp/gdp_esri/qe262_2
```

Or from the Actions tab: "Update data" → Run workflow (optionally push to a test branch).

### Raw MoSPI CPI indices (fixed, for analysis)
- `raw/in/cpi_full/cpi2024_{rural,urban,combined}.json.gz`: every 2024-base all-India series (general index, 12 divisions, 43 groups, 92 classes, 162 subclasses, 358 items), Jan 2025–Sep 2026, as returned by getCPIData (`tools/mospi_cpi_detail.py`). Divisions and groups match the press release Annexes I and II.
- `raw/in/cpi_full/groups2012_<year>.json.gz` (2013–2025) and `groups2010_<year>.json.gz` (2011–2014): every all-India group and subgroup index on the 2012 and 2010 bases, rural, urban and combined (`tools/mospi_old_groups.py`). The 2012-base current series starts in Jan 2013.
- `raw/in/cpi_old/items2012.json.gz` (299 items, 2014–2025) and `items2010.json.gz` (317 items, 2011–2014): all-India item indices (`tools/mospi_items_old.py`). MoSPI published no 2012-base item indices for Mar–May 2020; in_cpi_core imputes petrol, diesel, gold and silver for those months from market prices (below).
- `raw/in/fuel_ppac/ppac_metro_daily.json`: PPAC retail selling prices of petrol and diesel, Delhi, Mumbai, Chennai and Kolkata, daily from 16 Jun 2017 (`tools/ppac_rsp.py`, parsed from PPAC's PDF). `raw/in/gold_rbi/gold_silver_mumbai_2019_2021.json`: RBI monthly average gold and silver prices in Mumbai, Apr 2019–Mar 2021 (RBI Bulletin table). Used to impute the 2012-base item indices for Mar–May 2020: the Feb 2020 index moved with the monthly average price, benchmarked to MoSPI's Jun 2020 index.

### If MoSPI extends the 2024-base back series beyond the general index
`in_cpi_mospi` counts division/group/item rows in MoSPI's back series on every run and, when any appear, writes an "ACTION" warning to its release.json (the daily dashboard task reports it). Then: pull the back-series components with `tools/mospi_cpi_detail.py` (series "Back"), rebuild core 1 and core 2 before 2025 from them with the 2024-base item weights instead of the 2012-base residual linked over 2025, and calculate the contributions within the 2024 basket throughout. The 2012-base inputs, the Mar–May 2020 imputation and the chain-linked contributions would then only be needed for any years the back series does not cover.

### India producer prices (`sources/in_ppi_oea`)
Office of the Economic Adviser (DPIIT), 2022-23 base, monthly index files from download_data_2223.asp: Output PPI (goods, basic prices, Apr 2023 on; All commodities and the four major groups), trial Input PPI for manufacturing (Mar 2026 on; sector and 22 industry groups) and WPI (All commodities and major groups) → `data/in/ppi/in_ppi.csv`. Spliced output PPI → `in_ppi_spliced.csv`: Output PPI from Apr 2023, linked to WPI 2011-12 All commodities (Apr 2012 on, fixed file `raw/in/ppi_oea/wpi1112_monthly_index_202606.xls`) by the ratio of geometric means over FY 2024-25 (the OEA's own linking year); check: the same method on WPI reproduces the OEA's published 1.53. y/y from the linked index. Checked only once a new month is due (OEA releases on the 14th).

### Singapore CPI weights and contributions (`sources/sg_cpi_singstat`)
SingStat publishes no weights table and no contributions. Within each basket (2014, 2019 and 2024 bases: Jan 2014–Dec 2018, Jan 2019–Dec 2023, Jan 2024 on) the published all-items index is an exact fixed linear combination of its components, so the coefficients are solved by least squares over the basket's months and accepted only if every month is reproduced within 0.01 index points (actual: about 0.001, i.e. rounding). On the 2024 base these are the 2024 weights; item weights come from the same identity applied node by node down the classification (157 items, summing to 1). Contributions across a basket change use old weights before and new weights after; SingStat's linking gap at the change (−0.003 index points in Jan 2019, −0.073 in Jan 2024) is spread across parts by weight. Parts sum to the all-items y/y within 0.01pp. Fitted weights and residuals are written to `data/sg/cpi/sg_cpi_weights.json`.

### South Korea CPI weights and contributions (`sources/kr_cpi_ecos`)
ECOS publishes the 2022 basket weights (per 1,000) with every item. The CPI is a Lowe index: with the 2022 basket linked in at December 2022, I_t = I_L × Σ w_i (I_i,t / B_i) / Σ w_i (I_i,L / B_i), where B_i is the item's 2022 average index. This reproduces the published all-items index within 0.01 index points from the 458 items and within 0.014 from the special aggregates (weights are published to one decimal), and is checked every run (limit 0.03). Contributions use the same coefficients for months whose year-earlier month is on the 2022 basket (Dec 2023 on); parts sum to all items within 0.05pp. The ministry rebases to 2025 with the December 2026 CPI (published 31 Dec 2026): the source then stops with an ACTION error until LINK, BASE_YEAR and item codes are updated.

## Public site (`site/`)
A standalone copy of the Singapore dashboard for any static host. `site/sg/` holds the page (same page code as the claude.ai dashboard, with `shim.js` standing in for the dashboard runtime: it loads the CSV/JSON files and runs the page's calculations); `site/build.sh` assembles `public/` from it and the latest `data/sg/` files. On Cloudflare Pages: connect this repo, build command `bash site/build.sh`, output directory `public`; every pipeline commit to main then redeploys with the new data. To copy later changes from the claude.ai dashboard, save its `files` documents as JSON and run `python3 site/sync_from_dashboard.py <folder>`.
